Completed 2026-11-17 (overnight performance pass): streaming and saving. (1) A streaming reply is no longer re-parsed and replaced whole on every frame: finished blocks stay in the DOM and only the tail after the last safe cut (`stableCut` in `media/main.js`) is rebuilt. An 80 KB reply cost 113 s of main thread and 249 ms p95 frames before, 9 s and 27 ms after (`test/stream-performance.mjs`, `--old` for the comparison); `test/stream-incremental.mjs` checks 42 differently chunked streams against a full render. (2) The extension host no longer stalls on long chats: checkpoints (text, tool boundaries, session ids, drafts) used to stringify the whole chat, re-read and parse the existing file for the ownership check, copy it to .bak and stat every tool output, all synchronously, every 250 ms. They now reuse the serialised settled history (`ChatStore.serialise`, `settled` hint from `ChatRun.settledCount`), skip the parse while the file is unchanged since this store's own last commit, refresh the backup at most every 15 s and write less often when a write is slow. On an 11.5 MB chat the event-loop p99 stall fell from 107 ms to 19 ms. Behaviour change: session ids and tool boundaries are written within about 50 ms off the host thread, not synchronously; final saves are unchanged. (3) Reply text goes to the window in batches of about 33 ms (`ChatRun.postEvent`), flushed before anything else is sent and before a window attaches or replays. (4) Settled turns use `content-visibility: auto` (`style.css`): scrolling a 150-turn chat took 4.7 s of main thread instead of 10.1 s, accessibility tree unchanged. (5) Startup: the first Manage Chats / recent-chats listing after a restart parsed every saved chat on the extension host's thread (2.4 s for 285 chats, 350 MB). Summaries are now also kept in `session/chat-summaries.json`, keyed by each snapshot's stamp, so a cold listing took 81 ms on the real folder (`ChatStore.loadIndex`/`writeIndex`; a damaged or older-schema index is ignored). ## Maintaining this file

Give each new task a stable ID, status section, concrete next action and completion criterion. Record the request date when known; don't invent dates or priorities. Keep detailed designs in `docs/plans/` and link them here. Deferred means wait until selected; needs investigation means no confirmed fix yet.

When work finishes, remove its open checkbox and leave a short dated evidence link in Recently closed. Keep that section short; Git retains older history. Move superseded plans to `docs/archive/`, update incoming links and label them historical. Never silently drop an unresolved user request because it is old.
