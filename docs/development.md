## Development

Run `npm.cmd install`, `npm.cmd run check`, and `npm.cmd test` from this folder. Browser checks use Playwright and the installed Edge browser. To install into VS Code and/or Antigravity IDE on any OS (no PowerShell), run `node scripts/install-extension.mjs [vscode|antigravity|all]` (or `npm run install:extension`). It builds `out/ai-chat-panel-<version>.vsix` and installs it with the editor CLI (`code`, `antigravity`) when on PATH, otherwise copies into the extensions folder. Add `--link` to symlink/junction this checkout for live development, `--vsix-only` to just build the package (install via **Extensions: Install from VSIX...**), or `--dir <path>` for a custom extensions folder. The legacy `ai-chat-panel/install-into-antigravity.ps1 -Link` still works on Windows.

First-run onboarding (`#cliSetupModal`, also reopenable anytime via **Chat Settings > General > Setup guide**) connects your installed coding CLIs (Claude Code, Codex, Antigravity, and GitHub Copilot), links directly to **Voice** (Groq Whisper dictation) and **Routing** (free Cloudflare + Groq Auto router), and includes **Set up with AI** to prefill a guided setup and provider-customization prompt. The GitHub Copilot CLI foundation lives in [`ai-chat-panel/lib/providers/copilot.js`](../ai-chat-panel/lib/providers/copilot.js); see [docs/adding-a-provider.md](adding-a-provider.md) to fine-tune flags, models, or stream events.

Use the [project guide](../ai-chat-panel/PROJECTS.md) to choose the website, Visor, or Clanker as a chat's destination. They have independent Git roots. The current chat model supports one primary project per conversation; several open chats can target different repositories. Project registration doesn't itself grant or restrict filesystem access.

Visor is optional. The bridge smoke check discovers `../Visor` or `VISOR_DIR`. Clanker stores chats, schedules and attachments in per-user extension storage, so moving this source repository doesn't move that history.

Open chat editor tabs and pop-outs use Antigravity IDE's native layout restoration. Leave them open when closing the IDE to reopen them in their saved locations with the same conversations and drafts. Each restored webview requests its conversation after its message listener is ready, including when several windows reopen together. Closing an individual chat tab removes it from that layout; its history remains in Manage Chats. Window placement depends on the IDE restoring its previous session.

Onboarding has two screens: **Step 1, connect your CLIs**, then **Step 2, choose favorite models**. The second screen hosts the same Available models list as Settings, with search, CLI filters, refresh and favorite hearts. Back returns to connections; Start chatting finishes setup. Favorite changes use the existing Settings save path and appear in both places.

Tool cards show their output as a view that fits the tool, not a wrapped text dump (`media/tool-format.js` reads the shape, "Tool output views" in `media/main.js` draws it, `.tv-*` in `style.css`). A file read is code with a sticky line-number gutter and the editor's Shiki colours; Grep groups matches by file (a header or line number opens the editor there); Glob is a file list; WebSearch is a link list over its summary; a shell step shows the full command, then its output with terminal colours kept and failures, warnings and diffs tinted; an edit is a coloured diff with signs in the gutter. Wide lines scroll sideways (the bar's first button wraps them), copy gives the code without line numbers, and the expand button opens the same view large in the preview window. Views are built when a card first opens, and output of an unknown shape stays plain text. `test/tool-format.test.js` covers the parsers and `test/tool-views.mjs` the cards in a real page.

## IDE palette

Glass depth has separate tokens for controls, panels, menus, popovers, modals, the composer and content bubbles. Light mode brightens raised surfaces within the IDE palette, replaces broad shadows with small contact shadows, and removes the resting shadow from message bubbles. Dark-mode token values retain their existing geometry and opacity. Neutral cast shadows are disabled in high contrast. The `glass-depth-*` browser scenarios cover the rail, transcript, composer, model menu and Settings at 900/420/320px.

Liquid glass (`media/liquid-glass.js`): Chromium can run an SVG filter as a `backdrop-filter`, so each surface in `KINDS` gets one `<filter>` per size: an `feImage` displacement map (red = x, green = y, inward along the rounded-rectangle normal, strongest at the rim) fed to three `feDisplacementMap`s at slightly different scales for the colour split. The script sets `--lg-bd` on the element and adds `body.lg-on`; `style.css` reads it with the plain blur as fallback. Add a surface by adding a selector to `KINDS` and, if it needs the clear fill, to the `body.lg-on` rule. A surface inside another backdrop root (the goo-filtered composer, anything under `.fs-modal`'s blur) can't refract: its backdrop is empty. `buildMap` is pure and covered by `test/liquid-glass.test.js`. Review it in the `glass-depth-*` scenarios.

The dock is glass as well (`island()` in the same file): `.island-glass` is a fixed layer behind `.compose-row`, masked by the goo silhouette that `islandMask` draws from the shapes' rectangles (pure, tested), lit by `islandLight`, with a refracted bezel ring built from the same lens tiles. It redraws while anything in the dock animates and settles ~160ms after. Keep its backdrop blur at or under ~10px (Chromium leaves text crisp near the viewport edge with more). The glass is child layers, not pseudo-elements: `.ig-frost` (the blur, masked by the silhouette minus the ring), `.ig-tint`, `.ig-light`, and, once settled, `.ig-rim` strips (`rimBoxes`) that bend the backdrop along each shape's edge. Keep it that way: a backdrop filter reruns whenever anything inside its box changes, so one filter over the whole dock made every keystroke in the composer cost 60 to 100 ms; the middle of the pill must stay outside every strip (`liquid-glass.test.js` checks it). The rim strip is opaque inside the ring and the frost on top is soft (`1 - a`), which gives the original `(1 - a) * frost + a * bent`; two soft layers would weigh the bend `a^2`. Masks and the lighting image are set inline, never through custom properties (an inherited property holding a multi-kilobyte image is re-resolved by every descendant on every style recalc), and never list a pseudo-element such as `::before` inside `:is()` (the browser drops the whole rule, which is how the dock's tint and lighting once vanished without an error). See `docs/dynamic-island-composer-spec.md`. Composer shape, bar order, the single stop/send slot, the dictation lock, the permission chip and the upper-slab @ / lists: `node ai-chat-panel/test/composer-bar.mjs` (fake host, no model calls). Narrow panels: the bar stays one line and a scheduled prompt stays two lines; text goes in a fixed order (permission text, model name, clock time; on a row: "at reset", time, model name) and returns in reverse. `fitComposerBar` in `media/main.js` measures the bar and sets `fit-*` classes on `.composer`; rows use container queries on `queued-turn`. `node ai-chat-panel/test/narrow-layout.mjs` sweeps 13 widths.

This follows Apple's guidance to reduce shadow opacity over plain light backgrounds and keep content quieter than floating controls ([Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/), [Materials](https://developer.apple.com/design/human-interface-guidelines/materials)). These CSS materials do not implement native refraction or dynamically sample scrolling content underneath them.

Clanker follows the IDE's actual palette through webview `--vscode-*` variables. `media/theme-palette.js` maps host backgrounds, foregrounds, buttons, links, borders and status colours onto the existing glass tokens; missing optional colours are derived from the host background and foreground. Hosts without a usable background retain the built-in light/dark palettes in `media/style.css`.

Keep provider branding, project artwork, white glass highlights and dark-icon backings independent of the palette. The adapter checks text/button contrast and uses opaque surfaces in high-contrast themes. It watches host colour changes and emits `clanker-theme-changed` so SVG-painted bubbles repaint even when switching between two dark or two light themes. It does not reload the webview or replace drafts.

Verify with `node --test ai-chat-panel/test/theme-palette.test.js ai-chat-panel/test/theme.test.js` and the `ide-palette-*` UI scenarios. Browser fixtures cover coloured light/dark palettes, high contrast, same-kind live switches and missing-host fallbacks; actual IDE host integration still needs a reload and a live check. Keep reports and baselines outside synced folders.

## Usage windows and CLI maintenance

If Claude returns a Cloudflare-branded HTTP 403 authentication failure, Clanker pauses the affected chat queue and keeps the failed request first (or queues Continue if work was already performed). Further Claude sends are blocked until you explicitly allow a retry. Check the provider status page before retrying, then resume the paused queue manually. A successful local sign-in check alone cannot confirm that the provider has recovered.

Open chats linked to Codex check their native thread every two seconds for messages continued in ChatGPT. New prompts, reply text and supported tool records update automatically, including growing replies, while preserving the composer draft. Clanker waits while the external turn is active; stop that turn in ChatGPT. Sync requires the same locally accessible Codex thread and a running IDE. It pauses while Clanker runs its own turn. Deleted or forked threads, attachments and provider-specific UI may not mirror completely.

Pasting or dropping files creates local preview chips immediately. Image resizing/encoding and the asynchronous host save run afterward, correlated by request ID. Enter waits for pending saves before sending or queueing; the composer text is read-only during that wait to preserve the submitted draft. Save failures cancel the send and retain the text. Switching chats cancels the waiting send, and late attachments return to their originating draft. Pending preview paths are excluded from persisted drafts. Regression: `node ai-chat-panel/test/paste-attachments.mjs` (fake host, no model calls).

Codex permits only one writer per thread. ChatGPT may retain that ownership after its answer finishes. If Clanker reports it is waiting for the chat to be released, close the conversation in ChatGPT, or quit ChatGPT if it stays locked. Clanker keeps the pending prompt and retries every five seconds; Stop cancels it. Reading shared history does not grant simultaneous write access.

When a task hits its usage limit, Clanker automatically schedules Continue for the reset in the same chat, model and project, ahead of later prompts. This is on by default; turn off **Automatically continue after usage resets** in **Chat Settings > General** to use the manual Continue button instead. The IDE must remain running for scheduled prompts to dispatch.

Claude prompts waiting for the same reset share a deadline: reset readings up to one minute apart use the later time, including when restoring an older saved queue. Calendar schedules and separate usage windows keep their own times.

Reorder queued and scheduled prompts in one composer list, including while another reply runs: drag any part of a row that isn't a button, or use the up and down arrows above and below its `#1`, `#2`, ... number (the first row has no up arrow, the last no down arrow, a lone prompt none). The number is the place in the send order. Prompts send strictly from top to bottom. A scheduled row at the top holds everything below it until its time and usage requirements are met; another available model does not skip past it. The next row starts after the current turn finishes. The saved mixed order survives reload and applies to both dispatch paths. “Continue” can be dragged like any other prompt. The arrow-only Send button at the right end of a row (Send Now) remains a manual action.

Scheduled rows show attached images/files with the same thumbnail and count badge as queued turns. Hover the badge for filenames; narrow windows reduce it to a compact count.

To continue with another provider, click **Change model** on the scheduled prompt, pick a model, and confirm with the checkmark. Changing providers removes the old provider's reset deadline and sends when the chat is idle and the selected provider has usage and is signed in. Changing models within the same provider keeps its reset wait. **Ctrl+Enter** from the edited composer steers immediately; ordinary confirmation keeps the prompt queued. Calendar and timer schedules retain their chosen time.

**Start usage windows early** (**Chat Settings > General**, on by default) keeps each provider's 5-hour window (plus Gemini 4 Argon's separate 7-day window on Pro plans) rolling in the background, so one is nearly always already under way when you start. Whenever a window isn't running and no prompt is queued for its usage reset (that prompt starts the window itself), Clanker sends "respond with 1" to the cheapest model of that pool (`Gemini 4 Argon Low` for Argon), from an empty temporary folder with tools and project settings off. It only applies to CLIs signed in with a subscription: one that is billed per token through an API key (an API key in its environment or settings, or Codex in API-key mode) is never pinged. That repeats every 5 hours (7 days for Argon; a failed ping is retried up to 3 times, 10 minutes apart). The settings row shows what each ping used. The IDE must be running.

**Cloud usage windows** (**Chat Settings > General > Start windows in Google Cloud**, off by default) can run Claude Code and Codex warmups against a weekly work calendar while the PC is off, in your own Google Cloud project. It requires the Google Cloud CLI, billing-enabled project, deployment and separate cloud subscription sign-ins. Google Cloud may charge for incorrect setup or usage outside its shared free allowances. There is no shared Clanker backend. Antigravity is not supported by the cloud runner. See [setup, costs, credentials, pause and removal](cloud-usage-windows.md).

Migration recovery files live in `.migration-backup/`, which Git ignores. Visor holds the original Git bundle and working-tree snapshot. No GitHub remote or push is implied by the split.

**Automatically update idle CLIs** (**Chat Settings > General**, on by default) silently installs available updates for connected providers when they have no active work and you have not typed with that provider for 30 seconds. Claude can update while you use ChatGPT/Codex, and vice versa. Typing in Auto mode protects all providers until the idle period ends. Versions are checked at startup and every 6 hours; deferred updates are reconsidered every 15 seconds. Failed attempts wait 6 hours before retrying and remain available for manual update. Turn the toggle off to update manually. The IDE must remain running.

Pending updates and failed attempts also recheck the installed version every minute and when Settings opens. If another updater finishes, Clanker refreshes the version, clears stale errors and removes the update button automatically, without an IDE reload. This status refresh also runs when automatic installation is off.
